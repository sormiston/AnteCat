# App foundation

**Type:** Frontend infra, no screens with real data yet. Depends on ticket 2's grants; prerequisite for `SPEC.md`'s Phase 1 build.

**Goal:** Everything needed before a screen can render real data: tooling installed, the Supabase client and auth wired, the route skeleton in place.

## Decisions
- `order/_layout.tsx` renders `<Stack />`, not the `<Slot />` `SPEC.md`'s Realtime section names — a `Slot` collapses the list and detail into one screen of the parent stack, losing the push animation and back button both user journeys depend on. The Realtime hook mounts the same in either.
- Styling is NativeWind (Tailwind utility classes via `className`), not plain `StyleSheet` + `theme.ts` — see `docs/technical/frontend.md`.
- Data fetching is TanStack Query; raw `supabase.from(...)` calls stay out of components.
- Auth guarding at the route-layout level is a UX convenience only, not a security boundary — RLS doesn't exist yet, accepted as a temporary trust call for one seeded syndicate per `SPEC.md`.
