# Grant authenticated access

**Type:** Backend only, no app code. Backend prerequisite for `SPEC.md`'s Phase 1 build.

**Goal:** Give the `authenticated` Postgres role the grants it needs to read and write through PostgREST/Realtime at all — currently only `service_role` has any grants, so a logged-in demo user's client can't touch a single row.

## Decisions
- Grants added to the existing `supabase/migrations/20260901162710_grant_service_role_privileges.sql` rather than a new migration — per CLAUDE.md, this project develops against a local-only Supabase stack, so migrations are edited in place.
- No RLS. A flat grant is the accepted posture for this phase (`SPEC.md`'s Architectural Decisions), matching the single-syndicate trust model.
- Stake commit stays a single upsert (`ON CONFLICT (order_item_id, user_id) DO UPDATE`), which requires `check_stake_capacity`'s own-row exclusion in `20260822221600_create_order_item_stakes_and_triggers.sql` to change from excluding by `stake_id` to excluding by `user_id`, so the upsert path computes capacity correctly against everyone else's committed quantity.

## Tasks
- [ ] `GRANT USAGE ON SCHEMA public TO authenticated;`
- [ ] `GRANT SELECT ON syndicates, syndicate_members, products, product_bundle_thresholds, product_price_tiers, order_item_resolution TO authenticated;`
- [ ] `GRANT SELECT, UPDATE ON orders, order_items TO authenticated;` — the `UPDATE` grant is needed because `sync_order_item_quantity`/`sync_tiered_unit_price` run `SECURITY INVOKER` and so execute as whichever role wrote the triggering stake or status change.
- [ ] `GRANT SELECT, INSERT, UPDATE, DELETE ON order_item_stakes TO authenticated;`
- [ ] `GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO authenticated;`
- [ ] `ALTER PUBLICATION supabase_realtime ADD TABLE orders, order_items;`
- [ ] Change `check_stake_capacity`'s own-row exclusion from `stake_id` to `user_id` in `20260822221600_create_order_item_stakes_and_triggers.sql`.
- [ ] A narrow view over `syndicate_members ⋈ auth.users` to label a stake's owner on screen — nothing currently exposes member identity past `user_id`.
- [ ] Upsert coverage in `ledger-integrity.test.ts`.
- [ ] New anon-key `authenticated-access.test.ts`, following `helpers.ts`'s fixture-from-live-DB shape.
