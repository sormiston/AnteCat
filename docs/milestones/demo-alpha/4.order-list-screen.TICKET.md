# Order list screen

**Type:** Frontend feature. Depends on ticket 3's app foundation.

**Goal:** The order item list screen renders real seeded data, with admin close/execute actions gated by role.

## Decisions
- No client-side bundle-remainder splitter or resolution mirror — `apportion_bundle_stakes` and `order_item_resolution` are server-derived; duplicating either here would just be a second place the rule can drift (`SPEC.md`'s Architectural Decisions). `resolution.ts` is the exception `SPEC.md`'s Realtime section calls for: reading the view would be the second query key that section forbids, so the function mirrors it and the test file is written as that contract.
- No dedicated role-guard component — the admin close/execute action is a plain conditional on `domain/roles.ts`'s `isAdminOfSyndicate`, inline on `order/index.tsx`.
- The `['order', orderId]` query is rooted at `orders`, not `order_items` as `SPEC.md`'s Realtime section writes it: the list screen needs `status`, `deadline_at` and `opened_at` too, and rooting there keeps it one request under one key instead of adding the second key that section forbids. Stakes are nested for the same reason — ticket 5 needs every member's, and fetching only the viewer's would have to be widened.
- The order id is pinned as `DEMO_ORDER_ID = 1` rather than resolved. One seeded order exists and this milestone ships no picker; the shortcut is one constant, so a picker later changes one file.
- Capacity is drawn as what it is, not as one generic bar: countable marks for a `threshold_bundle` (an indivisible pack split between countable members), a proportional bar for a capped `tiered` item, and neither for an uncapped one. This is `SPEC.md`'s "capacity means two different things" made visual, and it is why the two pricing models get structurally different cards.
- Irreversible admin actions arm on first press and commit on second. `Alert.alert` is a no-op on web and this demo runs on iOS, Android and web at once, so the confirmation is built from portable primitives.

## Verification
Driven headless against the local stack with Playwright, signing in as real seeded users.

- **Both seeded items render correctly.** Widget 6-Pack shows 5 of 6 marks, €50.00 the pack, €8.33 each; Bulk Gizmos shows the 0–4 / 5–9 / 10+ ladder with €24.99 live and "2 more and everyone pays €21.50 each".
- **Admin sees close/execute and a member doesn't.** `admin@example.test` gets "Close the order early"; `member4@example.test` gets no admin control at all.
- **Closing re-apportions the bundle to exactly 5000.** The seeded pack sits at 5 of 6, so a sixth unit was staked first, taking the stakes to 4998 — two cents short, as the floored unit price guarantees. Closing through the admin button left `orders.status = closed` and `SUM(stake_amount) = 5000`, and member4's share read €16.67 in the UI where it had read €16.66. Seed restored with `supabase db reset` afterwards.
- **Not-authorized is distinguishable from a network error.** With a member's `syndicate_members` row removed, that user gets "Not your table" with no retry button, and the header band withholds the syndicate name and deadline.
- `pnpm test` green (88), `tsc --noEmit` clean, `expo lint` clean, `expo export --platform web` prerenders all 10 routes.
