# Order list screen

**Type:** Frontend feature. Depends on ticket 3's app foundation.

**Goal:** The order item list screen renders real seeded data, with admin close/execute actions gated by role.

## Decisions
- No client-side bundle-remainder splitter or resolution mirror — `apportion_bundle_stakes` and `order_item_resolution` are server-derived; duplicating either here would just be a second place the rule can drift (`SPEC.md`'s Architectural Decisions).
- No dedicated role-guard component — the admin close/execute action is a plain conditional on `domain/roles.ts`'s `isAdminOfSyndicate`, inline on `order/index.tsx`.

## Tasks
- [ ] `src/domain/`: `pricing.ts`, `capacity.ts`, `deadlines.ts`, `roles.ts`, `resolution.ts` — pure, unit-tested from `tests/domain/`. Move `helpers.ts`'s existing price math here.
- [ ] `src/features/orders/api.ts`: one query under `['order', orderId]` (single `order_items` select per `SPEC.md`'s Realtime section — do not fetch `order_item_resolution` from the client, do not add a second query key), plus admin close and execute mutations.
- [ ] `order/index.tsx` and its components: `OrderStatusBadge`, `DeadlineCountdown`, `OrderItemCard` (`ResolutionBadge`, `CapacityMeter`, current price, viewer's own stake if any).
- [ ] Shared `EmptyState`, `ErrorState`, `LoadingSkeleton`, distinguishing network-error from not-authorized states.

## Verification
- Both seeded items render correctly.
- Admin sees close/execute and a member doesn't.
- Closing re-apportions the bundle to exactly 5000.
